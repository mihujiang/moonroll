# 架构与决策记录

这份文档回答三个问题：每一层为什么存在、关键取舍是什么、哪些方案被明确否决了。

如果你只想跑起来，看 `README.md`；想改代码，先看这里的「一帧的生命周期」。

## 一句话定位

moonroll 把「确定性模拟 + 输入冗余重发 + 落后帧回滚重放」做成一个 sans-IO 库：
它不碰 socket、不碰渲染、不关心你的世界长什么样，只要求你提供一个能
`save` / `restore` / `step` / `hash` 的 `Sim`。

## 一帧的生命周期

```
前端采样输入
   │
   ├─ Session::advance(input)
   │     ├─ 记录本地输入到 InputRing[local]
   │     ├─ frame += 1
   │     └─ simulate(frame): sim.step(a, b) → 存快照 + 存哈希
   │
   ├─ 编码：最近 N 帧输入 + 确认帧 + 校验和帧 → encode_batch → 发送
   │
   └─ 收到对端包
         ├─ Input 帧：若该帧已模拟过 → replay_from(该帧)（回滚）
         │              否则 → 只记录，等模拟到该帧再用
         ├─ Confirm 帧：更新对端水位
         └─ Checksum 帧：和本地 hash_at(该帧) 比对，不一致就报告分叉
```

`sans-IO` 的代价是调用方要自己驱动收发；收益是整条链路能在单进程里跑，
所以 122 个测试里绝大多数都是「两个 Session + 两条模拟链路」的完整对局。

## 逐模块

### `fixed`：Q16.16 定点数

跨后端可复现的前提。`wasm-gc` 和 `native` 对 `f64` 的 FMA 合并、中间精度处理
并不保证一致，一个 `a * b + c` 就可能出现末位差异，而回滚要求「同一输入
必须得到逐位相同的状态」。定点数把这类问题从根上消掉，代价是要自己实现
`mul` / `div` / `sqrt` 和饱和。

### `digest`：64 位状态哈希

用于两个目的：本地快照去重（可选）和两端一致性探测。用 64 位是因为它只是
「探测」而不是「防伪造」——1800 帧的对局里发生一次碰撞的概率可以忽略，
而 64 位刚好能塞进协议的一个 varint。

### `input`：输入环与快照环

帧号是连续的，所以两者都是定长环形数组：`slot = frame % capacity`，写入时
顺带记下 owner 帧号，读取时比对帧号就知道槽位是不是别人的。相比 `HashMap`
省掉了哈希和分配，且在 wasm 里行为完全可预测。

窗口之外的帧会被自动覆盖——这正是「快照最多回滚 N 帧」的实现，也是
`hash_at` 在超出窗口后返回 `None` 的原因。

### `session`：状态机

`Session` 持有 `Sim`、两个 `InputRing`（本地 / 对端）、`SnapshotRing`、`HashRing`。

- **确认帧**的判定：`confirmed = min(两端都已收到的最高连续帧)`。不需要单独
  的确认包——输入包里带帧号，收到即有信息。
- **回滚**：`replay_from(base)` 先 `sim.restore(snapshots[base])`，再逐帧
  `simulate` 到当前帧。所以「恢复必须精确」不是可选项：漏一个字段，重放就会
  得到不同的世界。
- **历史哈希**（V0.4 新增）：每次 `simulate` 都记录 `hash_at(frame)`。分叉判定
  必须比**已确认帧**上的哈希，因为两端当前帧的预测输入合法地不同。

### `protocol`：字节编码

三类消息：`Input`（帧号 + 输入位图）、`Confirm`（帧号）、`Checksum`（帧号 + 哈希）。
全部 varint（LEB128），一个批包以消息条数开头，后面按 `tag` 分派。
`decode_batch` 对截断输入返回「已解析的部分」，这样半包不会毒化整条连接。

### `sim_net`：确定性链路模拟

`Link(delay, jitter, loss_pct, reorder_pct, seed)` 内部是 LCG，同种子同发送序列
必然得到同到达序列。抖动是通过在 `[0, jitter]` 上抽取额外延迟实现的，所以
后发的包确实可能先到——测试里专门断言了「逆序交付确实发生」。

这不是为了「好看」：如果链路不确定，端到端测试就只能 flaky。

### `adapters/phys`：moonphys 适配

`PhysSim` 把 `moonphys.World` 包成 `Sim`：

- `save` → `World::save_state()`（位姿、速度、暖启动冲量、世界时钟）
- `restore` → `World::load_state()`（**重建**一个从未运行过的世界，而不是原地改字段）
- `hash` → `World::state_hash()`

这一步暴露了一个重要细节：如果 `save` 只存「刚体引用」，`restore` 之后两端
共享的还是同一份内存，回滚就成了空操作。存成字节、由 `load_state` 重建，
是唯一能保证「恢复即隔离」的做法。

### `demo`：wasm-gc 演示引擎

两个独立物理世界 + 两条链路，每帧互发最近 8 帧输入。导出全是数值 ABI
（`i32` / `f64`），因为 JS 侧不需要理解 MoonBit 的字符串或结构体——这层
胶水越薄，页面越不容易和库版本漂移。

`mr_selftest()` 内置了 1800 帧的验收跑：200ms 延迟 + 50ms 抖动 + 25% 乱序，
要求 `desync == 0`。

## 关键取舍

| 决策 | 被否决的方案 | 为什么 |
| --- | --- | --- |
| 快照是不透明 `Bytes` | 要求 `Sim: Clone` 并 clone 对象 | clone 出来的对象往往共享内部 `Arc`，`restore` 后状态还是脏的；强制序列化能逼作者想清楚「哪些字段属于状态」 |
| 全量快照 + 重放 | 增量快照 / 逆操作回滚 | 逆操作要求每个系统都写对称的 undo，耦合度高、容易漏；128 帧窗口每帧几十字节，内存完全可接受 |
| 定点数 Q16.16 | `f32` / `f64` | 浮点在 wasm 与 native 之间的 FMA、舍入差异会让回滚后的世界对不上；这是「能不能用」的问题，不是精度问题 |
| 分叉判定比已确认帧历史哈希 | 比当前帧哈希 | 两端当前帧的预测输入合法地不同，比当前帧会产生大量假分叉。V0.4 实测 1800 帧里报了 517 次假阳性 |
| 输入冗余 8 帧 | 每条输入单独重发直到确认 | 冗余 8 帧后一次性补齐，包数从 O(帧数) 降到 O(1)/帧，实现也简单 |
| 校验和单独发 `Checksum` 帧 | 塞进 `Input` 包 | 混在一起会让「输入」和「状态确认」耦合，出问题时无法区分是输入错还是模拟错 |
| 链路模拟器用 LCG | 系统 `rand()` | 端到端测试必须可复现，否则 CI 会随机红 |
| wasm 只导出数值 ABI | 导出结构体 / 字符串 | 页面侧零胶水，且不会因为库内部结构变化而崩 |

## 已知限制

- **带宽**：没有增量压缩，每帧包大小约 `8 帧 × 输入`，在 2 玩家场景下可以接受，
  但玩家数增加时需要改成 delta 编码。
- **只支持 2 玩家**：`advance(local_input)` + 一个对端输入环；N 玩家需要改成
  输入表 + 广播。
- **不做反作弊**：64 位哈希只用于一致性探测，不防伪造；也没有延迟/输入频率分析。
- **物理快照不支持关节**：`moonphys::World::load_state` 对含关节的世界直接拒绝
  （关节约束需要额外的求解器状态，当前没有序列化）。
- **回滚深度未做上限自适应**：窗口固定 128 帧（约 2.1 秒），超过就退化为
  「放弃回滚、直接接受分叉」。
